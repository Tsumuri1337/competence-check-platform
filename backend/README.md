# Competence-check platform — backend

Проверка компетенций на основе действующих профессиональных стандартов
Минтруда России в области информационной безопасности. Кандидат или
сотрудник проходит по выбранному профстандарту самооценку (по желанию),
тест знаний и практическое задание; ревьюер оценивает практическое
задание и видит сводный (для кандидатов — также комплексный) отчёт.

## Профстандарты

Пять действующих профстандартов (группа 06 «Связь, информационные и
коммуникационные технологии», реестр Минтруда):

| Код | Название | Приказ |
|---|---|---|
| 06.030 | Специалист по защите информации в телекоммуникационных системах и сетях | №536н, 14.09.2022 |
| 06.032 | Специалист по безопасности компьютерных систем и сетей | №533н, 14.09.2022 |
| 06.033 | Специалист по защите информации в автоматизированных системах | №525н, 14.09.2022 |
| 06.034 | Специалист по технической защите информации | №474н, 09.08.2022 |
| 06.053 | Специалист по информационной безопасности в кредитно-финансовой сфере | №739н, 28.11.2022 |

Полная структура каждого стандарта (обобщённые трудовые функции → трудовые
функции → знания/умения) транскрибирована из официальных PDF и хранится в
`src/content/*.json` (источник для `seed.js`). Транскрипция сделана
построчным визуальным чтением отрендеренных страниц PDF (не через
автоматическую суммаризацию — см. `HANDOFF.md`), поэтому это реальный,
проверяемый по первоисточнику текст:

| Код | ОТФ | ТФ | Знаний+умений | Вопросов теста | Практич. заданий |
|---|---|---|---|---|---|
| 06.030 | 7 | 20 | 215 | 22 | 2 |
| 06.032 | 5 | 20 | 387 | 20 | 2 |
| 06.033 | 4 | 21 | 294 | 20 | 2 |
| 06.034 | 12 | 38 | 588 | 25 | 2 |
| 06.053 | 6 | 25 | 380 | 24 | 2 |

Тест знаний и практическое задание — авторский контент, составленный на
основе этих знаний/умений, а не цитаты из стандарта. Самооценка охватывает
100% транскрибированных пунктов каждого стандарта; квиз и практическое
задание выборочно покрывают структуру (см. «Что не реализовано» ниже).

## Стек

Express (`src/server.js`) + Postgres через `pg` (`src/db.js`, тот же
`transaction()`-паттерн, что и раньше). Соединение читается из
`DATABASE_URL` (см. `.env.example`); по умолчанию — локальный dev-адрес
`postgresql://hr_poc_app:hr_poc_app_dev@localhost:5432/hr_poc`.

## Запуск

Нужен запущенный Postgres (локально или через `DATABASE_URL`).

```bash
npm install            # Express, pg, cors
npm run migrate        # применяет src/schema.sql
node src/seed.js       # загружает 5 профстандартов + демо-контент
node src/server.js     # http://localhost:3001
```

Обе страницы раздаются backend'ом напрямую из корня проекта:
`http://localhost:3001/test_flow.html` (прохождение проверки) и
`http://localhost:3001/reviewer_dashboard.html` (панель ревьюера).

## Данные и роли

- **Кандидат/сотрудник** — не авторизуется, указывает ФИО/email и контекст
  (`employee`/`candidate`) при старте проверки.
- **Ревьюер** — PoC-заглушка аутентификации через заголовок
  `X-Reviewer-Email` (как раньше `X-User-Email`) — открытая заглушка,
  годится только для локальной разработки.

## Что реализовано

- Пять профстандартов с полной структурой ОТФ/ТФ/знания/умения.
- Три этапа проверки, в порядке прохождения: самооценка (по желанию,
  всегда предлагается и всегда пропускаема — см. ниже), тест знаний
  (авто-оценка), практическое задание (оценка ревьюером по рубрике,
  завершает проверку). Самооценка идёт первой, а не последней, чтобы
  собственная оценка навыков не была искажена уже увиденным результатом
  теста.
- Валидация анкеты и ответов на клиенте: формат email, обязательные поля,
  непройденные вопросы/задания/пункты самооценки подсвечиваются и
  прокручиваются в поле зрения перед отправкой.
- Сводный отчёт для ревьюера: результат теста, статус практического
  задания, самооценка по каждому пункту.
- **Комплексный отчёт** для обоих контекстов: сводка «% по тесту / средний
  балл по практическому заданию / пройдена ли самооценка». Для кандидатов
  (`context=candidate`) под сводкой добавляется решение по найму —
  `accepted` / `rejected` / `pending`, сохраняется через
  `POST /api/assessments/:id/decision` и видно в списке проверок ревьюера.
  Для сотрудников это только сводка, без каких-либо кнопок решения — оценка
  их дальнейшей судьбы вне объёма этого среза.
- **«Скачать PDF»** в комплексном отчёте — не отдельная генерация PDF, а
  печать браузера (`window.print()`) с выделенным print-стилем: список,
  фильтры, полный текст заданий/рубрик и построчная самооценка скрываются,
  остаётся сжатая сводка на 1-2 страницы (имя, стандарт, баллы, решение).
  Пункт «Сохранить как PDF» есть в диалоге печати любого современного
  браузера — отдельная зависимость не нужна.
- Журнал доступа — каждый просмотр отчёта, оценка задания и решение по
  кандидату записываются в `access_log`.

## Что не реализовано (сознательно, следующие шаги)

- Реальная аутентификация (кандидат/сотрудник и ревьюер).
- Единый "combined score" — сейчас комплексный отчёт показывает
  тест/задание/самооценку раздельно, без формулы итогового балла.
- Полноценный банк вопросов на каждое знание/умение — тест знаний и
  практическое задание сейчас выборочно покрывают структуру стандарта, не
  каждый пункт.
- Шифрование персональных данных на уровне приложения.
- Развёртывание Postgres на инфраструктуре в РФ (152-ФЗ ст. 18.5) — сейчас
  локальный dev-инстанс.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/standards` | Список профстандартов |
| GET | `/api/standards/:code` | Полное дерево ОТФ/ТФ/знания-умения |
| POST | `/api/assessments` | Начать проверку (person + standardCode + context) |
| GET | `/api/assessments/:id` | Статус проверки |
| GET | `/api/assessments/:id/quiz` | Вопросы теста знаний (без правильных ответов) |
| POST | `/api/assessments/:id/quiz-responses` | Отправить ответы, получить балл |
| GET | `/api/assessments/:id/practical-task` | Практическое задание(я) |
| POST | `/api/assessments/:id/practical-submission` | Отправить решение |
| GET | `/api/assessments/:id/self-assessment` | Пункты для самооценки |
| POST | `/api/assessments/:id/self-assessment` | Отправить самооценку (не завершает проверку — см. выше) |
| GET | `/api/assessments?standardCode=&context=&status=` | Список проверок (нужен `X-Reviewer-Email`) |
| GET | `/api/assessments/:id/report` | Сводный + комплексный отчёт (нужен `X-Reviewer-Email`, журналируется) |
| POST | `/api/assessments/:assessmentId/practical-submissions/:submissionId/score` | Оценка практического задания (завершает проверку, когда оценены все задания) |
| POST | `/api/assessments/:id/decision` | Решение по кандидату: `accepted`/`rejected`/`pending` (только `context=candidate`) |

Демо-ревьюер после `seed.js`: `reviewer@example.ru`.
